# 薄肌俱乐部 · 数据模型

> 状态：训练模型已落地（`src/lib/training.ts`），小镇游戏原型已完成（`src/game/`），饮食待优化。

## 总览

```
AppState (v3, localStorage: tmc:v3)
├── profile          测评答案
├── startDate        计划开始日期
├── intensity        训练强度系数（根据反馈 0.7–1.4）
├── days[date]       DayLog：睡、吃、水、身体数据（按天）
├── sessions[]       TrainingSession：训练记录（单独存，可跨天、可进行中）
├── game             GameState：场景布局 + 角色外观（只存选择，不存进度）
└── chat[]           AI 对话（OpenAI 消息格式）
```

**写入入口统一走操作函数**：`ops`（store.ts，睡吃水身体）和 `trainingOps`（training.ts，训练和设施）。App 界面、游戏、AI 工具调用用的是同一套函数，所以无论数据从哪个入口进来，结果都一致。

## 日期的含义（凌晨 4 点换天）

`date` 字段（饮食、喝水、训练、每日日志）表示这条记录**归属哪一天**，按"凌晨 4 点换天"计算：00:00–03:59 仍算前一天（`packages/core/src/day.ts` 的 `appToday()`，App、小镇、AI 共用）。

真实时间另外保存，不受换天规则影响：所有表的 `created_at` / `updated_at`（服务器时间，UTC）、训练的 `start_at` / `end_at`、睡眠的入睡 / 起床钟点、今天记录的饮食的 `eaten_at`（补录过去的日子时为空）。需要按自然日统计时，用这些真实时间重算即可。

## 四个支柱

| 支柱 | 存在哪 | 记录方式 | 复杂度 |
|---|---|---|---|
| 睡 | `DayLog.sleep {bed, wake, quality}`，记在醒来那天 | 点击 / AI | 低 |
| 水 | `DayLog.water`（ml） | +250 按钮 / AI | 低 |
| 吃 | `DayLog.meals[] {slot, text, protein, kcal}` | 表单 / AI 估算 | 高，**待优化** |
| 练 | `sessions[]` | 游戏 / App 跟练 / AI / 手动 | 高，见下文 |

## 训练方式（测评时选择，"我的"页面可以切换）

| | App 安排（`trainingMode: 'app'`，默认） | 自己安排（`'own'`） |
|---|---|---|
| 测评 | 问经验、器械、每周 3–5 天、每次 15/20/30 分钟 | 跳过经验和器械；每周 2–6 次、每次 30–90 分钟 |
| 今日页 | 课表卡片 + App 跟练 | 训练记录卡片（本周已练 X/Y 次），去小镇记录 |
| "练"的完成度 | 训练日练了 = 1；计划休息日 = 1 | 今天练了 = 1；否则看本周节奏：截至今天应练 `floor(每周次数 × 本周已过天数 / 7)` 次，跟上了 = 1。本周中途开始计划的，从开始那天算起 |
| 测评结果页 / 进展页 | 每周课表 | 本周实际训练列表 |
| 小镇 · 我的小屋 | 有"App 跟练" | 没有 |
| AI 教练 | 知道今天的课表 | 知道用户自己安排，不主动排课 |

## 热量账本 `src/lib/energy.ts`

每天按真实数据动态计算，不是固定目标：

```
今日消耗 = 基础代谢(Mifflin，用最近一次记录的体重) + 日常活动(基础代谢 × 30%) + 运动消耗(当天训练记录)
今日预算 = max(保底, 今日消耗 + 目标调整)
剩余     = 预算 − 已摄入(各餐 kcal 之和)
```

| 项 | 规则 |
|---|---|
| 目标调整 | 纤细型 +250 / 准薄肌型 −200 / 隐藏线条型 −250 / 蓄力型 −450 |
| 保底 | 不低于基础代谢，也不低于 女 1200 / 男 1500 |
| 运动消耗 | 只来自训练记录（MET 估算），基础部分不含运动，不会重复计算 |
| 未填热量的餐 | 不计入摄入，首页提示"让小薄帮你估算" |
| 近期平均差 | 只统计记录完整的日子（≥2 餐且都有热量），按 7700 kcal ≈ 1 kg 脂肪换算成每周变化 |
| 测评页参考值 | 同一公式，把计划训练量折算到每天，显示为"日均约" |

超出预算时不建议第二天少吃补回来（首页文案和 AI 提示词一致）。

## 训练模型

### 原则：训练记录是唯一数据源，游戏状态全部推算

```
写入入口：游戏场景 · App 跟练 · AI 聊天 · 手动补录
                 ↓
      TrainingSession（唯一数据源）
                 ↓ 推算（不存储）
角色等级 · 属性 · 设施等级 · 体型阶段 · 过程分 · AI 上下文
```

- 在聊天里补记一次游泳，场景里的游泳馆同样涨经验。
- 删除一条错误记录，所有游戏数值自动回退。
- 不存在"游戏数据和训练数据对不上"的问题。

### 运动项目目录 `src/data/activities.ts`（静态）

| 设施 | 项目 |
|---|---|
| 我的小屋 home | App 跟练、居家训练、跳绳 |
| 健身房 gym | 力量训练、有氧器械、团课 |
| 游泳馆 pool | 游泳 |
| 跑道 track | 跑步、快走 |
| 瑜伽馆 yoga_studio | 瑜伽、普拉提 |
| 球馆 court | 羽毛球、篮球 |
| 公园 park | 骑行、散步、其他运动 |

每个项目有 `category`（力量/耐力/柔韧/球类/日常）和 `met`（代谢当量），热量估算公式为：`MET × 体重 × 小时`。

### TrainingSession

| 字段 | 说明 |
|---|---|
| `activityId` / `title` | 项目；自定义名称（如"夜跑"） |
| `facilityId` | 在场景里的哪个设施练的（可空） |
| `source` | `game` / `guided` / `chat` / `manual` |
| `status` | `active` 进行中 / `completed` |
| `startAt` `endAt` `pausedAt` `pausedMs` | **时长由时间戳计算**，不依赖前台计时器 |
| `date` | 归属日期，以开始时间为准 |
| `rpe` | 主观强度：轻松 / 刚好 / 累（第一版只记这个，不记组数重量） |
| `kcal` | 默认按 MET 估算 |
| `details.exercises` | App 跟练自动填写每个动作的组数和次数/秒数 |

### 生命周期

```
start ──► active ──pause/resume──► finish(endAt 可修正, rpe) ──► completed
            └──────────── discard ────────────┘
add（AI / 手动补录）──────────────────────────────► completed
```

- 同一时间只允许一条进行中的训练。
- **手机锁屏**：网页计时器在后台会暂停，所以只记时间戳，结束时用实际时间计算。
- **忘记结束**：超过 `STALE_MS`（3 小时）的进行中记录，下次打开时询问实际结束时间（UI 待做）。

### 推算规则（奖励坚持，不奖励过量）

| 数值 | 规则 |
|---|---|
| 计入时长 | 少于 5 分钟不计；单次最多计 90 分钟 |
| 单次经验 | 完成 10 分 + 每 2 分钟 1 分（最多按 60 分钟算） |
| 每日经验 | 上限 60，防止为了升级虚报或过度训练 |
| 角色等级 | 第 n 级需要 `50 × (n-1)²` 经验：Lv2=50，Lv3=200，Lv4=450 |
| 角色属性 | 力量 / 耐力 / 柔韧 = 对应类别的累计计入分钟 |
| 设施等级 | 在该设施累计 60 / 300 / 900 / 2000 分钟 → Lv2–5 |
| 体型阶段 0–4 | 按"达标周"数（一周完成计划次数的 75%）：1 / 3 / 6 / 10 周 → 阶段 1–4。**镜子还没变化时，角色先变** |

### GameState

只存用户的选择，不存进度：
- `facilities[] {id, kind, name?, pos{x,y}}`：场景里摆放的设施，默认有"我的小屋"。删除设施不会删除训练记录。
- `avatar {skin, outfit}`：角色外观。
